# 協作方式(怎麼跟這個人一起工作)

> 【這是範本】複製到新專案的 `docs/dev/collaboration.md`,把內容改成你自己的
> 偏好。**下面每一條的「Why」都是通用的**(它們來自實際踩過的協作失誤),
> 「How to apply」才需要按人調整。
>
> ⚠️ **「必須當場生效」的幾條要抄一句到 `CLAUDE.md`** ——只寫在這裡等於沒寫,
> 這一份要有人想到去讀才會載入,而 `CLAUDE.md` 是每次對話自動載入的。
>
> ⚠️ 這一份講的是「**怎麼一起工作**」,不是程式怎麼寫。
> **開始討論規格、或要動介面之前請先讀完。**

## 1. 回覆語言

<!-- 範例:一律用繁體中文(台灣用語),不必等提醒。 -->

**Why:** 專案的硬性慣例通常規範的是**程式產出**(UI 文案、錯誤訊息、註解),
**不包含對話裡講的話**——不明講的話兩邊會不一致。

**How to apply:** 預設就用指定語言,不要等提醒。專有名詞、API 名稱、程式碼、
檔案路徑、log 原文照原樣保留(翻譯反而查不到)。對方用其他語言提問時仍照舊,
除非他明講要換。

## 2. 規格討論:主動補他沒想到的盲點

收到需求時,不要照單全收——**主動指出需求裡的盲點**。

**Why:** 提需求的人對自己的領域清楚,但對「技術上還有哪些同類情境」不一定
掃得全;漏掉的情境等到實際使用時才發現,成本高得多。

**How to apply:**

- 先給建議,再主動列「你沒提到、但同類情境常見的」,分成
  **強烈建議一起做 / 順手幾乎免費 / 先不做要另外談**三級讓他挑。
- 同時**誠實講出每個選項的代價**(工作量、效能、失真),不要只列可能性。
- ⚠️ **「產物給誰用」要在最前面問**。真實教訓:一次需求討論到**第七輪**
  對方才補一句「產物主要是給 AI 讀的,不是給人看的」,
  **那一句推翻了三件已經定案的事**(表格呈現方式、圖片處理策略、失真標記形式)。
  **輸出物的消費者反向決定保真度、格式與結構,比「支援哪些格式」更早該問。**

## 3. 介面改動:先出設計稿,通過才動程式碼

UI / 版面變更一律先出模擬圖 + 方案對照(A 案 / B 案),讓對方選案。

**Why:** 直接改碼會跳過他的決策點,而那通常代表**整段白做**。

**How to apply:** 選案時**把代價一起量化**(「整欄 +24px、按鈕下移 24px」),
那是他做決定需要的資訊。通過之後才動程式碼,並在提交訊息裡記下選了哪一案、
為什麼。

## 4. 改了使用者看得到的行為,就主動更新說明

不必等對方提醒。判準是「**使用者看得到的行為變了沒有**」:

- **新功能 / 改掉既有行為** → **一定**要在同一批改動裡更新說明文件,
  **不要另開一次提交**
- **修 bug / 小調整** → 只要讓使用者看到的東西變了(訊息、按鈕、產出內容),
  照樣要更新;純內部重構、效能、註解則不必
- ⚠️ **不確定該不該動說明時就問**,不要自己省略——對方寧可被問一句,
  也不要事後發現說明跟程式對不上

⚠️ **改文案 = 拿舊字串 `grep -rn` 全 repo,不要憑記得去改那幾個檔。**
改完再搜一次確認零殘留,**搜的範圍要含 `.md`**(README 與各種文件都可能
引著同一句話)。真實教訓:同一批改動連著改五個標籤,前四個都記得同步文件,
第五個仍漏掉一個章節標題。**失守的從來不是規則,是「靠記得」這個做法。**

## 5. 「請記住這件事」= 寫進 repo

聽到「記住 / 記憶下來」時,**寫進版控的檔案**,不是寫進記憶功能。

**Why:** 記憶功能存在使用者家目錄、綁機器又綁專案路徑,`git clone` 到另一台
電腦完全不會跟過去;而很多人換電腦的方式就是**複製專案資料夾**。

**How to apply:**

- **必須當場生效**的 → `CLAUDE.md`(唯一每次自動載入的檔案)
- 領域細節 → `docs/dev/*.md`,並在 `CLAUDE.md` 留一句觸發語指路
- 寫完**說清楚寫進哪個檔**,好讓對方知道換機器之後還在
- **一併提交推送**

## 6. 例行維護可以長期授權

某些變動每次都問一遍只是浪費彼此時間(例:資料檔的例行更新)。
可以請對方給一次長期授權,之後**看到有變動就直接提交,不再問**。

⚠️ **二進位檔案的提交訊息要寫清楚「什麼變了、變了多少」**——
檔案本身看不出差異,不寫的話事後完全無從得知。而且**位元組差異會嚴重高估
變動量**(一次「先刪後補」的寫入會讓整片資料位移,實測 148 列裡 105 列
對不上,真正變動的只有 3 筆)。
