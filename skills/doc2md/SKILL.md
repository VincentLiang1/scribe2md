# 文件 → Markdown(讀文件之前先做這一步)

**先轉再讀,不要直接 Read 二進位文件。** 理由依格式而異——PDF 與掃描件是**成本**,Office 檔是**保真度**:

| 檔案 | 直接讀 | 轉成 md 之後 |
|---|---|---|
| .docx / .pptx / .xlsx / .msg | Read 工具不解析。這些是 ZIP 包 XML,`unzip -p x.docx word/document.xml` 剝掉標籤能拿到純文字,但**表格會糊成一片、內嵌圖抽不到**,且三種格式的 XML 佈局各不相同 | 表格保留結構、內嵌圖抽出去重並 OCR、同一組指令吃所有格式 |
| 簡報式 PDF(字少版面大) | 每頁當圖片,約 1500~2000 token,內容可能只有幾十個字 | 約 100~200 token/頁 |
| 文字密集 PDF | 同樣逐頁圖片 | 純文字,約省 2~3 倍 |
| 掃描件 / 照片 | 圖片進 context,還要自己認字 | OCR 過的文字 |

> [!IMPORTANT]
> **別把 Office 檔說成「讀不了」。** 這句話講出口而沒實際試過,代價是那些檔案會被當成不存在、就這樣躺著不處理——而且錯誤宣稱會自我封存,沒有人會回頭去查一件「已經確認做不到」的事。`unzip` 這條路隨時可用,所以本工具買的是**保真度與一致性、不是可能性**。純文字 docx 兩者的 token 量其實差不多(實測 16.4k vs 17.6k 字元,轉檔還略多一點),值得用的理由是**表格結構與內嵌圖**。

## 指令

```bash
uv run --directory {{MEETING_SCRIBE_DIR}} doc2md "<檔案或資料夾>"
```

可以一次給多個路徑。常用選項:

- `--out-dir "<資料夾>"` — 產出集中到別處。**別人的文件資料夾就用這個**(預設會在原檔旁邊留下 `.md` 與 `.assets\`)。這個模式下檔名會多一段內容雜湊(`簡報.pdf` → `簡報-3f9a2b71.md`),因為集中輸出會把不同資料夾的同名檔攤到同一層;同一份文件永遠對到同一個 md(重跑免費)、原檔改過則自動重轉。**照 stdout 給的路徑去 Read,不要自己拼檔名。**
- `--prune-days N` — `--out-dir` 那個資料夾裡**超過 N 天的舊產出自動清掉**(預設 14 天,`0` = 都不清)。集中輸出的檔名帶內容雜湊,原檔改過就多一份新的 md、舊的不會被蓋掉,所以快取只增不減。**不必自己去刪**:這次還要用到的、以及不是本工具產生的檔案都不會被清,沒有 `--out-dir` 時完全不清(那時產出在使用者自己的文件旁邊)。
- `--no-ocr` — 不做文字辨識。掃描頁與圖片只留標記,但快非常多。
- `--dry-run` — 只列出會轉哪些、會跳過哪些,不寫檔(也會列出這次會清掉哪些過期快取)。大批次先跑這個。
- `--speakers N` / `--model {fast,accurate}` — 只作用在錄音錄影(見下)。

## 錄音與影片(m4a / mp3 / wav / mp4 / mov / avi)

也吃,轉出來是**繁體中文逐字稿**(標「講者 1／2／3」,不做真人姓名命名)。

> [!WARNING]
> **這跟文件不是同一個量級。** 一份 PDF 幾秒鐘,**一場兩小時的會議要跑一小時上下**(沒有 GPU 更久)。把使用者的資料夾整個指過去之前,先用 `--dry-run` 看看裡面有沒有錄音檔;真的要轉,**先告訴使用者會跑多久再動手**,不要讓一個「看一下這個資料夾」變成一小時沒有回應。工具自己也會先在 stderr 提醒有幾個錄音檔。

要**真實姓名**(而不是「講者 1」)的話,命令列做不到——講者編號每個檔案獨立分群,命名必須一檔一檔當場做。請叫使用者開網頁介面(`uv run --directory {{MEETING_SCRIBE_DIR}} meeting-scribe`)、一次選一個檔案。
- `--no-recursive` — 給資料夾時不往子資料夾找。

## 輸出契約

- **stdout 一行一個 md 的絕對路徑**,沒有其他文字 → 直接把每一行拿去 Read。
- **已經轉過、這次被跳過的也會列出來**。所以重複執行是安全且近乎免費的,不必自己判斷「轉過了沒」。
- 人看的摘要與失敗清單走 stderr。
- 離開碼:`0` 全部順利 / `1` 有檔案失敗(其餘仍完成,失敗原因在 stderr)/ `2` 什麼都沒做 / `130` 被中斷。

## 讀 md 時要注意的幾件事

產出是**為了餵 AI 設計的**,檔頭的 YAML frontmatter 是機器可讀的:

```yaml
lossy: 4
lossy_kinds: [merged_cells, chart, ocr, encoding_guess]
ocr_used: true
```

1. **`ocr_used: true` = 內容有一部分是機器認的,可能有錯字。** 引用數字或人名前先提醒使用者核對原件。
2. **`lossy_kinds` 說明轉檔時丟了什麼**(圖表、樞紐、儲存格底色、追蹤修訂…)。內文對應位置有繁中的 〔 〕 標記——**看到〔〕就知道那裡原本有東西**,不要當成內容缺漏去腦補。
3. **每份 md 只有一個 H1**(文件標題),內容從 H2 起;超寬表格(>12 欄)會轉成「逐筆區塊」而不是 markdown 表格。
4. **看到〔本工作表是為列印排的並排版面…〕就以小節為準。** 分機表、機櫃圖這類「一張紙上左右並排好幾塊」的試算表,從屬關係只靠版面位置表達,工具已經依區塊拆成各自的小節、標題就是那一塊的名稱(部門名、機櫃編號)。**不要拿原檔的「同一列」當成同一筆**——那一列橫跨好幾個區塊。⚠️ 這個標記在**內文**、不在 frontmatter(它不是失真,沒有東西丟掉);若寫的是「但資料量太大、這次沒有依區塊還原」,那就**還沒**拆,同一列真的混著好幾個區塊。
5. **不要為了讀圖裡的字去開 `.assets` 裡的圖片。** 那些字**已經在 md 裡**了——就在圖片連結正下方,由〔以下文字由…辨識而來〕帶頭的段落。`.assets` 裡的圖是留給**人**核對原件用的,一張圖送進模型的成本遠高於它旁邊那段文字。只有這兩種情況才值得去讀原圖:
   - 需要**視覺資訊**:圖表的趨勢方向、顏色代表什麼、版面上誰對應誰——這些 OCR 表達不出來
   - 旁邊那段辨識文字明顯壞掉(亂碼、語意不通),而那段內容正好是關鍵

## 什麼時候**不要**用

- `.md`:直接 Read 就好,轉了沒有好處。**給資料夾時工具本身就會跳過裡面現成的 `.md`**(轉出來只是原樣副本),所以混合資料夾可以放心整個指過去。唯一值得轉的情況是 `--out-dir` 的知識庫攝入(要把 md 連同它引用的圖片一起搬進快取,或那份 md 是 cp950／UTF-16 需要自動判編碼)——那時**把檔名一個一個指名出來**,資料夾展開不會幫你收。
- `.txt`:同樣直接 Read 就好(這個沒有上面那條例外,給資料夾時仍會被轉)。
- `.csv`:**建議還是轉**——台灣的 csv 很多是 cp950(Big5),直接 Read 會是亂碼,而這個工具會自動判斷編碼。
- 只需要確認檔案存不存在、看檔名時。

## 要先跟使用者說一聲的情況

- **會在原始文件旁邊寫檔**(`<原檔名>.md` + `<原檔名>.assets\`)。如果那是別人的資料夾或共用磁碟,先問或直接用 `--out-dir`。
- **大批掃描件/照片很慢**:OCR 每張圖 1~3 秒。50 張圖的 PDF 大約要兩三分鐘,先講一聲或建議 `--no-ocr`。
- **想重新轉換已經轉過的檔案**,得先把舊的 `.md` 刪掉(工具刻意跳過已存在的,這是為了「資料夾陸續加新檔、重跑只處理新的」)。
- **`--out-dir` 的資料夾裡超過 14 天的舊產出會被自動清掉**(見上面的 `--prune-days`)。使用者若把重要的東西放在同一個資料夾裡不受影響——只清本工具產生的檔案——但值得在第一次用 `--out-dir` 指到某個資料夾時順口提一句。

## 其他

- 全程**地端離線**,不上傳任何內容;隱私敏感的文件可以放心用。
- 同一台機器上這個工具還有網頁介面(`uv run --directory {{MEETING_SCRIBE_DIR}} meeting-scribe`),使用者要自己操作、批次挑檔時可以建議他用那個。
- 網頁介面正在轉檔時不要同時跑這支 CLI,兩邊會搶 CPU。
